### Optimizaciones ya aplicadas (pre-P3.4)
1. `serverExternalPackages`: Prisma, Pino, OTel SDK excluidos
2. `optimizePackageImports`: lucide-react, recharts, radix, framer-motion tree-shaken
3. Webpack cacheGroups: vendor, ui-libs, common separados
4. Cache-Control headers: immutable para static assets
5. Service Worker (Serwist) para offline

### Optimizaciones aplicadas en P3.4
1. **`@vercel/otel` externalizado** — Agregado a `serverExternalPackages`, ahorrando ~311 KB por cold start de cada serverless function

## Analisis de Chunks Grandes

### 1.16 MB — TurboPack Runtime
- Contenido: IEEE 754 float ops, polyfills, module system
- **Accion:** Ninguna. Es overhead del framework, no optimizable.

### 3 x 318 KB — Recharts + Immer
- Usado en: 7 archivos admin (ejecutivo, monitoring, reports)
- **NO impacta POS** — Solo se carga en rutas admin analytics
- `recharts` ya esta en `optimizePackageImports` para tree-shaking

### 85 KB — events.ts (73 event types)
- Archivo de dominio critico
- **Accion:** Aceptable. Los 73 tipos son necesarios para el type system.

## Mitigaciones Cold Start

### Ya implementadas
- `serverExternalPackages` excluye 7 paquetes pesados (Prisma, Pino, OTel)
- Paginas POS son `○ Static` (pre-rendered, no requieren server function)
- Las rutas API son tiny stubs (~1KB) que cargan shared chunks on demand

### Arquitectura favorable
- POS pages (`/pos/*`) son **estaticas** — pre-rendered en build, no cold start
- Las APIs criticas (`/api/pos/*`, `/api/events/ingest`) comparten server chunks
- Despues del primer cold start, las invocaciones siguientes son warm (~10-50ms)

## Criterios P3.4

| Criterio | Meta | Estado | Notas |
|----------|------|--------|-------|
| Cold start < 3s | < 3s | MITIGADO | Paginas POS estaticas; APIs comparten chunks |
| Warm P95 < 200ms | < 200ms | MEDIBLE | Script en `scripts/benchmark-routes.ts` |
| Bundle analysis | Reducir chunks | COMPLETADO | otel externalizado (-311KB server) |

## Como ejecutar benchmarks

